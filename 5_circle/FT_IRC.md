## Introduction

**IRC(Internet Relay Chat)**는 인터넷에서 사용하는 텍스트 기반의 통신 프로토콜입니다.  
실시간 메시지를 주고받을 수 있으며, 공개 또는 비공개 방식으로 대화가 가능합니다.  
사용자들은 직접 메시지를 주고받거나 그룹 채널에 참여할 수 있습니다.

IRC 클라이언트는 IRC 서버에 연결하여 채널에 참여하며, IRC 서버들은 서로 연결되어 하나의 네트워크를 구성합니다.

## General rules

- 어떤 상황에서도 프로그램이 **크래시(비정상 종료)** 되어서는 안 됩니다.  
  (예: 메모리 부족 등으로 인해 종료되는 경우 포함)  
  만약 이런 일이 발생한다면, 해당 프로젝트는 **비정상 작동**으로 간주되어 **점수는 0점**이 됩니다.

- 소스 파일을 컴파일할 수 있는 **Makefile**을 반드시 제출해야 합니다.  
  이 Makefile은 **불필요한 재링크**를 수행해서는 안 됩니다.

- Makefile에는 최소한 다음과 같은 규칙들이 포함되어야 합니다:  
  `$(NAME)`, `all`, `clean`, `fclean`, `re`

- 소스 코드는 `c++` 컴파일러를 사용해 다음 플래그와 함께 컴파일해야 합니다:  
  `-Wall -Wextra -Werror`

- 코드는 반드시 **C++98 표준**을 따라야 합니다.  
  즉, `-std=c++98` 플래그를 추가하더라도 정상적으로 컴파일되어야 합니다.

- 가능하다면 항상 C++ 기능을 우선적으로 사용하도록 하십시오.  
  예를 들어, `<string.h>`보다는 `<cstring>`을 사용하는 것이 바람직합니다.  
  C 언어 함수 사용은 허용되지만, **가능한 경우 C++ 버전을 우선적으로 사용**하십시오.

- 모든 외부 라이브러리 및 **Boost 라이브러리 사용은 금지**됩니다.

| **제출 파일**       | - `Makefile`<br>- `*.h`, `*.hpp`<br>- `*.cpp`, `*.tpp`, `*.ipp`<br>- (선택) 구성 파일                                                                                                                                                                                                                                                                           |

| **사용 가능한 함수**   | C++98 표준 내에서 사용 가능한 시스템 함수들:<br>`socket`, `close`, `setsockopt`, `getsockname`,<br>`getprotobyname`, `gethostbyname`, `getaddrinfo`, `freeaddrinfo`,<br>`bind`, `connect`, `listen`, `accept`,<br>`htons`, `htonl`, `ntohs`, `ntohl`,<br>`inet_addr`, `inet_ntoa`, `send`, `recv`,<br>`signal`, `sigaction`, `lseek`, `fstat`, `fcntl`, `poll` (또는 동등 기능) |
| **Libft 사용**    | 사용 불가 (`n/a`)                                                                                                                                                                                                                                                                                                                                             |
| **프로젝트 설명**     | C++98 표준을 사용하여 개발하는 IRC 서버 프로그램                                                                                                                                                                                                                                                                                                                           |

C++98 표준을 사용하여 **IRC 서버**를 개발해야 합니다.
**IRC 클라이언트는 개발하지 않아야** 합니다.
**서버 간 통신(server-to-server communication)** 은 구현하지 않아야 합니다.

당신이 작성한 실행 파일은 다음과 같은 형식으로 실행됩니다:
```bash
./ircserv <port> <password>
```

- **`port`**: IRC 서버가 **클라이언트의 접속을 수신 대기**할 포트 번호
- **`password`**: 클라이언트가 서버에 접속할 때 사용할 **연결 비밀번호**

<span style="background:#40a9ff"> INFO </span>
>비록 `poll()` 함수가 과제 설명서와 평가 기준에 명시되어 있지만,  
>다음과 같은 **동등한 기능을 제공하는 함수**들을 사용해도 무방합니다:
>
>- `select()`
>- `kqueue()`
>- `epoll()`
>
>즉, `poll()` 대신 위 함수들 중 **플랫폼에 적합한 대안**을 자유롭게 선택하여 사용할 수 있습니다.


### Requirements

- 서버는 **여러 클라이언트를 동시에 처리할 수 있어야** 하며,  
  어떤 상황에서도 **멈추거나 정지(hang)** 되어서는 안 됩니다.

- **fork() 사용은 금지**됩니다.  
  모든 입출력(I/O) 작업은 **논-블로킹(Non-blocking)** 방식으로 이루어져야 합니다.

- 모든 동작(예: 읽기, 쓰기, 수신 대기 등)은  
  반드시 **단 하나의 `poll()` (또는 그에 상응하는 함수)** 로 처리해야 합니다.

<span style="background:#ff4d4f"> WARN </span>
>비차단(non-blocking) 파일 디스크립터를 사용해야 하기 때문에  `poll()` (또는 이와 동등한 함수) 없이도  `읽기(read) / 받기(recv)` 또는 `쓰기(write) / 전송(send)` 함수를 사용할 수 있으며,  이 경우에도 서버는 차단되지 않습니다.
>
>하지만 이러한 방식은 **시스템 리소스를 더 많이 소비하게 됩니다.**
>
> 따라서 `poll()`(또는 이와 동등한 함수)을 사용하지 않고  
> 파일 디스크립터에서 `읽기/받기` 또는 `쓰기/전송`을 시도할 경우,  
> 해당 프로젝트의 **등급은 0점** 처리됩니다.

- 여러 IRC 클라이언트가 존재하므로, 그 중 **하나를 기준(reference) 클라이언트**로 선택해야 합니다.  
  **선택한 클라이언트는 평가 과정 중에 사용됩니다.**

- 기준 클라이언트는 **에러 없이 서버에 정상적으로 연결 가능해야** 합니다.

- 클라이언트와 서버 간의 통신은 반드시 **TCP/IP (IPv4 또는 IPv6)** 를 통해 이루어져야 합니다.

- 기준 클라이트를 사용할 때, **공식 IRC 서버와 상호작용하는 방식과 유사해야** 합니다.  
  단, 다음 기능만 구현하면 됩니다:

 - 기준 클라이트를 통해 다음 작업을 수행할 수 있어야 합니다:
   - 인증(Authentication)
   - 닉네임 설정(NICK)
   - 사용자 이름 설정(USER)
   - 채널 참여(JOIN)
   - 개인 메시지 송수신(PRIVMSG)

  - **한 클라이언트가 채널에 보낸 메시지는 해당 채널에 참여한 모든 클라이언트에게 전달**되어야 합니다.

  - **운영자(Operator)** 와 **일반 사용자(Regular User)** 개념이 존재해야 합니다.

  - 그런 다음 채널 운영자 전용 명령을 구현해야 합니다:
   - `KICK` : 클라이언트를 채널에서 강제 퇴장시킴  
   - `INVITE` : 클라이언트를 채널로 초대  
   - `TOPIC` : 채널의 주제 확인 또는 변경  
   - `MODE` : 채널 모드 변경. 다음 모드를 구현해야 함:
    - `i` : 초대 전용 채널 설정/해제 (Invite-only)
    - `t` : `TOPIC` 명령을 운영자에게만 허용/해제
    - `k` : 채널 비밀번호 설정/해제 (channel key)
    - `-o`: 채널 운영자 권한 부여/취소
    - `l`: 채널에 대한 사용자 제한 설정/해제
 - 물론 깔끔한 코드를 작성해야 합니다.

## Test example

부분 데이터 수신, 낮은 대역폭 등 가능한 모든 오류와 문제를 확인합니다.

서버로 전송된 모든 데이터를 올바르게 처리하는지 확인하기 위해 다음과 같은 간단한 테스트를 수행할 수 있습니다:
```bash
\$> nc -C 127.0.0.1 6667
com^Dman^Dd
\$>
```
명령을 여러 부분으로 보내려면 ctrl+D를 사용하여 ‘com’, ‘man’, 'd\n'을 차례로 입력합니다.

명령을 처리하려면 먼저 수신된 패킷을 집계하여 다시 빌드해야 합니다.
